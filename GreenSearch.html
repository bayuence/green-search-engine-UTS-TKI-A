Inverted Index

Struktur data inti search engine. Setiap term dipetakan ke posting list berisi dokumen yang mengandungnya beserta posisi dan frekuensi kemunculan.

Konsep Inverted Index

Inverted Index memetakan setiap term ke posting list — daftar dokumen yang mengandung term tersebut beserta posisi kemunculannya. Memungkinkan pencarian yang sangat efisien O(1) per term.

// Struktur data
{ term → { df: int, postings: { doc_id: [pos1, pos2, ...] } } }

// Contoh
"ekonomi" → { df: 33, postings: { D1:[2], D3:[1,5], D6:[0,3,7], ... } }
"fiskal" → { df: 6, postings: { D10:[1], D11:[0], D20:[3], ... } }

Penjelasan Konseptual

IDF (Inverse Document Frequency) dirancang untuk memberikan bobot tinggi pada term yang langka dan bobot rendah pada term yang umum.

Alasan Matematis

// Term umum (df tinggi)
N/df ≈ 1 → log₁₀(1) = 0 → IDF rendah

// Term langka (df rendah)
N/df >> 1 → log₁₀(besar) = tinggi

Alasan Logis (Information Theory)

// Shannon: self-information
I(x) = -log P(x)

Kejadian langka → P rendah
→ I(x) tinggi → informasi lebih banyak
Prinsip inti IDF: "The rarer the term, the more informative it is." Kata yang jarang muncul dalam koleksi dokumen mengandung informasi lebih spesifik dan mampu membedakan (mendiskriminasi) dokumen satu dari lainnya dengan lebih kuat. IDF secara matematis mengimplementasikan prinsip ini.

Analisis Efek Normalisasi

Perbandingan hasil pencarian dengan dan tanpa Cosine Normalization. Kaitan dengan Vector Space Model.

Kueri Pengujian: "kebijakan ekonomi hijau indonesia"

Tanpa Normalisasi — Dot Product
Dengan Normalisasi — Cosine Similarity

Masalah Tanpa Normalisasi

Dalam VSM, skor relevansi dihitung sebagai dot product antara vektor query dan vektor dokumen. Dokumen panjang secara otomatis memiliki nilai TF-IDF akumulatif yang lebih besar.

Score(q, d) = Σ w(t, q) × w(t, d)

Dokumen panjang → banyak term → Σ w besar
Dokumen pendek → sedikit term → Σ w kecil
→ BIAS terhadap panjang dokumen!

Solusi: Cosine Normalization

Cosine Similarity membagi dot product dengan norma L2 kedua vektor, memproyeksikannya ke unit sphere. Skor hanya bergantung pada sudut antar vektor, bukan panjangnya.

CosSim(q, d) = (q · d) / (||q|| × ||d||)

||v|| = √(Σ v_i²) // norma L2
→ Semua vektor berunit length = 1
→ Perbandingan adil, bebas bias panjang

Analogi Praktis

Bayangkan dua artikel membahas topik yang sama:
Artikel A: 1.000 kata, menyebut "ekonomi hijau" sebanyak 10 kali
Artikel B: 100 kata, menyebut "ekonomi hijau" sebanyak 5 kali

Tanpa Normalisasi
A Menang
10 > 5 (raw count)
Dengan Normalisasi
B Menang
5/100 = 5% > 10/1000 = 1%
Kesimpulan: Artikel B lebih spesifik membahas topik tersebut (5% dari kontennya), meski secara absolut menyebut lebih sedikit. Normalisasi mengungkap relevansi sesungguhnya.

Evaluasi Sistem

Skenario pengujian dengan 2 kueri. Ground truth ditetapkan berdasarkan penilaian manual kelompok. Hitung Precision, Recall, dan F-Measure.

Formula Metrik Evaluasi IR

Precision = TP / (TP + FP)

// Dari yang diambil sistem,
// berapa yang benar-benar relevan?
Recall = TP / (TP + FN)

// Dari semua yang relevan,
// berapa yang berhasil ditemukan?
F-Measure = 2·P·R / (P+R)

// Harmonik mean antara
// Precision dan Recall

TP = True Positive (relevan & ditemukan)  |  FP = False Positive (tidak relevan, ikut diambil)  |  FN = False Negative (relevan, tidak ditemukan)

Trade-off Precision vs Recall: Dalam sistem IR, terdapat trade-off inherent antara Precision dan Recall. Meningkatkan nilai top-K akan meningkatkan Recall (lebih banyak dokumen relevan ditemukan) tetapi menurunkan Precision (lebih banyak dokumen tidak relevan ikut masuk). F-Measure sebagai harmonik mean membantu menemukan titik keseimbangan optimal.
